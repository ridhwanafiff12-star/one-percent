# Kaizen PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Kaizen, an offline, installable PWA that serves 4 evidence-based random daily tasks and tracks 1%-per-day compounding progress.

**Architecture:** Static site, no build step: vanilla ES modules served from GitHub Pages. Pure logic modules (`date`, `bag`, `day`, `score`, `store`, `backup`) hold all behaviour and are unit-tested with Node's built-in runner; thin UI modules render state with DOM APIs only. A service worker precaches the app for offline use.

**Tech Stack:** HTML/CSS/JS (ES2022 modules), `node --test` (Node 22), Playwright (pre-installed) for e2e, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-22-kaizen-design.md`

## Global Constraints

- No runtime dependencies, no CDN, no build step. Dev-only: none beyond Node 22 + the pre-installed Playwright.
- UI copy in English. App name exactly `Kaizen`.
- Categories, in this display order: `health`, `ibadah`, `knowledge`, `finance` (labels: Health, Ibadah, Knowledge, Finance).
- Day key = local date `YYYY-MM-DD`, boundary 00:00 local.
- Daily multiplier `1 + 0.01 * done/4`; missed day = ×1.
- Note max 140 chars, trimmed. Backup import max 1 000 000 chars.
- Storage key `kaizen.state`; corrupt copy key `kaizen.state.corrupt`; `schemaVersion: 1`.
- `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function` are banned in `src/`.
- CSP exactly as in the spec's Security §2, set by `<meta http-equiv="Content-Security-Policy">` in `index.html`.
- All paths relative (site lives under `/one-percent/`).
- Every task has `minutes` between 2 and 10 inclusive.

## Review Focus

1. **App reopened after several missed days** — gap days count ×1, streak resets to 0 (or 1 once something is done today), today's tasks generated fresh; no crash on absent days. → test in Task 5 and Task 6.
2. **App left open across midnight** — on `visibilitychange`/focus and every 60 s, if `dayKey(new Date())` changed, a new day is generated and screen re-renders; yesterday's state is untouched. → e2e in Task 11 using Playwright clock.
3. **Note or imported title containing `<img src=x onerror=alert(1)>`** — shown literally as text, no element created. → Task 10 e2e + Task 9 ban test.
4. **Corrupt or unavailable localStorage** (bad JSON, `setItem` throws QuotaExceeded, storage disabled) — app shows a banner, keeps working in memory, never overwrites the corrupt raw value. → Task 8.
5. **Library changes between versions** (task id removed or added in a later release) — stored days with unknown ids still render as "Retired task"; bags drop unknown ids and gain new ones. → Task 4 and Task 5.

Shared types (JSDoc in each module):

```js
/** @typedef {'health'|'ibadah'|'knowledge'|'finance'} Category */
/** @typedef {{id:string, category:Category, title:string, minutes:number, why:string, source:{label:string, url?:string}}} Task */
/** @typedef {{id:string, done:boolean, doneAt:string|null, note:string, rerolled:boolean}} Slot */
/** @typedef {Record<Category, Slot>} Day */
/** @typedef {{schemaVersion:1, firstDay:string, bags:Record<Category,string[]>, bestStreak:number, lastBackupAt:string|null, days:Record<string,Day>}} State */
```

All state functions are **pure**: they return a new `State` and never mutate input. `rng` is `() => number` in `[0,1)` (inject `Math.random` in the app, a seeded fn in tests).
